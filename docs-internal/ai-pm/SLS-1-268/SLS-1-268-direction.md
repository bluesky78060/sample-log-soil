# SLS-1-268 Discovery — 퇴비 엑셀 가져오기 E2E 공백

작성일: 2026-08-21 · 방향 확정: 사용자 승인 (2026-08-21, "응, 진행해줘")

## 1. 목표 (Why)

퇴비의 엑셀 가져오기는 **사용자가 실제로 쓰는 현역 경로**인데, 이를 지키는 E2E가
34줄짜리 스모크 하나뿐이다. 배선이 끊겨도 그 스모크는 통과한다.
이 티켓은 **회귀를 실제로 잡는 두께**로 검증을 올린다.

## 2. 사용자 (Who)

전국 농업기술센터·분석기관 담당자. 퇴·액비 시료를 엑셀로 일괄 접수한다.
가져오기가 조용히 깨지면 **접수 자료가 등록되지 않은 채 등록된 것으로 보인다.**

## 3. 범위 (What)

### 포함
- `tests/e2e/compost-import-flow.spec.js` 신규 — 모달 열기 → 컬럼 매핑 → 미리보기 →
  저장(localStorage 지속성) → 서식 다운로드
- 채번 단언 — 미리보기 번호와 저장 번호의 일치, 자동 채번 규칙

### 제외
- **소스 코드(`src/`) 변경 없음.** 이 티켓은 검증만 추가한다.
- 기존 `tests/e2e/compost-import-smoke.spec.js`는 **유지한다** — "공용 모듈 생존"이라는
  별개 축을 지킨다(SLS-1-224가 soil의 import를 끊을 때 필요했던 그 축).

### 사전 조사로 종결된 범위 ✅
티켓 본문의 "⚠️ 함께 확인할 것 — 채번 결함이 compost에도 있나"는 **코드 리딩으로 답이 나왔다.**

| 확인 항목 | 결과 |
| --- | --- |
| compost에 성토(`F` 접두) 개념이 있는가 | **없다.** `generateNextReceptionNumber()`(compost-script.js:1172)는 `parseInt` 최대값+1의 순수 정수 체계 |
| 공용 `_autoAssignReceptionNumbers`가 그것을 존중하는가 | **한다.** excel-import-manager.js:394가 같은 `parseInt` 최대값+i+1 규칙. 두 규칙이 일치 |
| 자동 채번의 발동 조건 | `hasReceptionNumbers` — 엑셀에 접수번호가 하나라도 있으면 **건너뛴다** |
| 미리보기/저장 번호 불일치 여지 | 구조적으로 좁다 — `_parsedLogs`에 번호를 쓰고 `onImportComplete`가 **그 객체를 그대로 push**. 두 번 계산하는 지점이 없다 |

→ **soil의 SLS-1-222 결함은 compost에 미발현이다.** 다만 "지금 없다"와 "앞으로도 없다"는
다르므로, 위 네 항목을 **E2E 단언으로 고정**해 미래의 회귀를 막는다.

## 4. 제약

- `npm test`는 `docs/`(vite 빌드 산출물) 대상 → **테스트 전 `npm run build` 필수**
- 레거시 importer는 **붙여넣기 모드가 없다.** soil의 새 importer(`SoilResultImporter`)와
  달리 실제 파일 업로드만 가능 → 브라우저 안에서 `window.XLSX`로 .xlsx를 만들어
  `setInputFiles`로 넣는다 (`soil-import-header-row.spec.js`의 검증된 패턴)
- 서식 다운로드는 `XLSX.writeFile()` → 브라우저 다운로드. Playwright `waitForEvent('download')`로 받는다

## 5. 우선순위

P3. 배포를 막는 결함은 아니나, **현역 경로가 무방비**라는 점에서 남은 4건 중 실익이 가장 크다.

## 6. 리스크

| 리스크 | 대응 |
| --- | --- |
| 새 테스트가 통과만 하고 아무것도 안 잡는 경우 | **변이 검증 필수** — 배선을 일부러 깨서 실제로 죽는지 확인하고 그 출력을 리뷰 문서에 남긴다 |
| `showToast`·`alert` 등이 테스트를 막는 경우 | `page.on('dialog')` 선처리 (기존 스펙과 동일) |
| 다운로드 테스트가 CI에서 불안정 | 파일 내용까지 파싱하지 않고 **파일명·시트 존재**만 단언해 표면을 좁힌다 |
| 이 티켓이 `src/` 를 건드리게 되는 경우 | **범위 이탈.** 결함을 발견하면 별도 티켓으로 올리고 이 티켓은 테스트만 남긴다 |

## 7. 검증

- 새 E2E 전 항목 통과 (`npm run build && npm test`)
- **변이 검증**: `setupExcelImport()` 호출 제거 또는 `_autoAssignReceptionNumbers` 훼손 시
  새 테스트가 **실제로 실패**하는지 확인 (출력 첨부)
- 기존 스모크 1건 + 전체 E2E 회귀 없음
- 단위 테스트 영향 없음 (`src/` 무변경)
