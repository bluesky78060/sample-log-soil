# SLS-1-273 Discovery — skipRowCheck 죽은 분기

작성일: 2026-08-21 · 사용자 승인: "남은 티켓 진행해줘"

## 1. 목표 (Why)

퇴비 엑셀 가져오기의 행 건너뛰기 판정이 **어떤 입력으로도 발동하지 않는다.**
농장명·대표자가 모두 빈 행이 **기본값만 걸친 쓰레기 레코드로 등록**되고,
건너뜀 경고도 뜨지 않아 사용자는 **정상 등록으로 인식한다.**

```js
const sampleType = getVal('sampleType') || '가축분퇴비';   // buildRecord — 항상 값이 들어간다
if (!record.farmName && !record.name && !record.sampleType) { … }   // 3번째가 절대 참이 안 된다
```

## 2. 사용자 (Who)

엑셀을 손으로 만들어 올리는 담당자. 마지막 행에 비고만 적어 두거나, 빈 행에 메모를
남기는 일은 흔하다. `_excelData`가 거르는 것은 "전 칸이 빈 행"뿐이다.

## 3. 어떤 행을 유효로 볼 것인가 — 업무 판단

세 선택지 중 **(a) 원본 셀 값을 보게 한다**를 택한다.
초안은 (c)였으나 **플랜 리뷰에서 뒤집혔다** — 아래 참조.

| 선택지 | 판단 |
| --- | --- |
| **(a) 원본 셀 값을 본다** | ✅ 채택. 원래 의도를 **그대로** 되살린다. 업무 정책을 바꾸지 않는다 |
| (b) `sampleType` 기본값 제거 | ❌ **위험.** 흙토람 내보내기가 `log.sampleType \|\| ''`로 받아(23열) 빈 시료종류가 그대로 업로드된다 |
| (c) `farmName`·`name`만 본다 | ❌ 아래 두 이유로 기각 |

### (c)를 기각한 이유 — 플랜 리뷰(codex)가 잡았다

**① 그래도 죽은 분기로 남는다.** `buildRecord`는 행에 대표자가 없으면
**공통 대표자(`common.name`)로 메운다.** 1단계에서 공통 대표자를 입력하면
`record.name`이 늘 채워져 (c)의 조건도 **다시 절대 참이 되지 않는다.**

> 즉 문제의 뿌리는 `sampleType` 기본값 하나가 아니라
> **"기본값이 적용된 `record`로 '비었는지'를 판정하는 것"** 자체다.

**② 업무 정책을 조용히 바꾼다.** (c)는 "농장명·대표자 둘 다 없으면 버린다"로
**인정 범위를 좁힌다.** 리뷰가 반례를 들었다 — 접수번호와 시료종류만 적어 두고
대표자는 나중에 채우는 일괄 접수, 주소·전화로 식별하는 기존 업무 파일.
결함을 고치는 티켓에서 정책까지 바꿀 이유가 없다.

### (a)의 내용

`skipRowCheck`에 **그 행의 원본 셀 접근자**를 넘긴다. 판정 대상 3필드는 **그대로 둔다**.
농장명·대표자·시료종류를 **사용자가 그 행에 하나도 적지 않았을 때만** 건너뛴다.
오늘과 달라지는 것은 **그 판정이 실제로 동작한다**는 것뿐이다.

## 4. 제약

- 공용 `excel-import-manager.js`의 `skipRowCheck` 계약은 **바꾸지 않는다.**
  대신 "record는 기본값이 적용된 뒤"라는 함정을 그 자리에 주석으로 남긴다
- 전건이 탈락하면 `_parsedLogs`가 비어 가져오기가 막힌다(기존 가드) — 의도한 동작

## 5. 우선순위

P3. 조용히 쓰레기 데이터가 쌓이는 축이다.

## 6. 리스크

| 리스크 | 대응 |
| --- | --- |
| 정상 행을 버린다 | 식별자 둘 중 **하나라도** 있으면 유지한다. 오늘보다 관대한 방향은 아니지만 잃는 것은 식별 불가 행뿐이다 |
| 사용자가 모르게 줄어든다 | `skipRowCheck`의 반환 문구가 **행 번호와 함께** 경고 영역에 뜬다 |
| 정상 경로 회귀 | `compost-import-flow.spec.js` 8건이 지킨다 |
