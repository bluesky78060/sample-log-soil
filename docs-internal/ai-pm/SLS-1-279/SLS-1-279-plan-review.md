## MAJOR — 퇴비 흡수 열은 **아예 동작하지 않는다** · **범위에서 뺐다**

플랜 초안은 퇴비의 농장주소(`col-farm-address`)에 `width: 100%`를 주려 했다.
codex가 그 열의 실제 CSS를 확인해 막았다.

```css
/* compost-style.css:759 */
.compost-navbar ~ .main-content .col-farm-address {
    width: 250px; min-width: 250px; max-width: 250px;
}
```

**재현**: `width: 100%`를 줘도 `max-width: 250px`가 이겨 **흡수가 일어나지 않는다.**
플랜대로 넣으면 "고쳤다"고 기록되지만 화면은 그대로다.

게다가 그 250px는 **두 줄 표시**(`white-space: normal`)를 위한 의도적 설계다.
억지로 풀면 그 설계가 깨진다. 주소(`col-address`)도 똑같다.

### 오케스트레이터 실측 — 발현 조건도 훨씬 넓다

| 화면 폭 | 퇴비: 표가 넘치나 | 폭이 바뀐 열 |
| --- | --- | --- |
| 1800 | 넘침 → 넘침 | **0개** |
| 2200 | 딱 맞음 → 넘침 | 16개 |

퇴비 표는 원래 2066px로 넓어 **2150px 이상**에서만 남는 폭이 생긴다(토양은 1700px).

**결정: 퇴비는 구분선 색만 고치고 흡수 열은 백로그로 남긴다.**

## MINOR — 퇴비 다크 색상이 플랜과 다르다 · **반영**

플랜에 "확인 후"라고만 적어 둔 자리의 실제 값은 `#14532d`(짙은 초록)였다
(`compost-style.css:1834`). 정확한 값과 바꿀 값을 표에 적었다.

## codex가 확인해 준 것 (문제 없음)

- 토양 `.col-lot-address { width: 100% }`는 의도대로 동작한다. `min-width`가 걸린
  다른 열들과 충돌하지 않는다
- `th`에 클래스를 추가해도 기존 코드에 영향이 없다 — 주소 검증 갱신
  (`soil-script.js:5605`)은 `td.col-lot-address`만 찾는다
- 공익직불제(`gongik-on`)·전체 보기(`full-view`) 모드와 충돌하지 않는다
- 구분선 색만 바꾸므로 SLS-1-260의 좁은 화면 고정 해제(토양 1024px, 퇴비 1200px)와
  다크 모드 규칙을 깨뜨리지 않는다
- 공용 `style.css`에 두는 것은 안전하다 — `col-lot-address`는 토양 목록에만 있고
  흙토람·설정·피드백·라벨 페이지의 `.data-table`에는 없다.
  다만 **공용 규칙이라는 사실을 주석으로 남기라**는 제안을 받아들였다
