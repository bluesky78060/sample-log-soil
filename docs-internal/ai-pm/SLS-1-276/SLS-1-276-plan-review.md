# SLS-1-276 플랜 리뷰

리뷰: 2026-08-27 · 리뷰어: **codex** (독립 레인, 저장소 직접 열람) + 오케스트레이터 확인

CRITICAL 0 · MAJOR 0 · MINOR 2 (반영) · SUGGESTION 2 (1건 반영, 1건 검증으로 흡수)

| # | 질문 | codex 답 |
| --- | --- | --- |
| 1 | `.table-container`가 정말 죽은 코드인가 | 그렇다. 유일한 등장이고 실제 컨테이너는 `.table-wrapper` |
| 2 | 채움 행이 기존 코드를 깨뜨리나 | 아니다. 행 순회는 전부 `.row-checkbox` · `tr[data-id]` 선택자 기반. 엑셀·라벨 인쇄·흙토람은 DOM이 아니라 `sampleLogs`와 선택 ID를 쓴다. **다만 채움 행에 체크박스나 `data-id`를 넣지 않아야 한다** |

## MINOR ① — 구분선과 채움 행의 열 수 계산이 갈라진다 · **반영**

thead 전체는 22열이지만 화면에 보이는 것은 기본 19 / 공익직불제 18이다.
thead 개수를 그대로 쓰면 기존 `_buildFarmSeparatorRow`의 하드코딩(18/19)과 값이 달라진다.
초과 `colSpan`은 브라우저가 잘라내 당장은 무해하지만, 플랜이 내세운 "같은 계산 공유"가
말뿐이 된다.

**재현**: 표에 표시 열을 하나 추가 → 채움 행은 자동으로 늘고 구분선은 그대로 → 폭이 갈라진다.

**반영**: `_visibleColumnCount()` 헬퍼를 만들어 **채움 행과 구분선이 함께 쓴다.**
`offsetWidth > 0`으로 숨긴 열을 걸러 세고, 표가 화면 밖이라 전부 0일 때는 19로 떨어진다.

## MINOR ② — 같은 방향 연속 이동에서 애니메이션이 재생되지 않는다 · **반영**

**재현**: 1→2, 이어서 2→3. 두 번 모두 `page-in-next`라 클래스에 변화가 없어 CSS
애니메이션이 다시 돌지 않는다.

**반영**: 클래스를 지우고 `void tbody.offsetWidth`로 한 번 끊은 뒤 다시 붙인다.
검증 항목에 "같은 방향 연속 이동에서도 클래스가 다시 붙는다"를 추가했다.

## SUGGESTION ① — 채움 행을 접근성에서 숨겨라 · **반영**

`pointer-events: none`은 스크린리더를 막지 못한다. `aria-hidden="true"`를 붙인다.

## SUGGESTION ② — 채움 행이 데이터 행으로 오인되지 않는 시험 · **검증 항목으로 흡수**

채움 행에 `.row-checkbox`도 `data-id`도 없음, 구분선 `colSpan`이 표시 열 수와 일치함을
유닛 검증에 추가했다.

## 오케스트레이터 확인

- MINOR ①의 폴백 `19`는 **기본 모드의 표시 열 수**다. 표가 화면에 없을 때만 쓰이고,
  그 순간에는 어차피 눈에 보이지 않는다. 값이 틀려도 다음 렌더에서 바로잡힌다.
- `_buildFarmSeparatorRow`를 함께 고치는 것은 **동작 변경이 아니다** — 현재 값과 결과가
  같음을 유닛으로 못 박는다(19/18).
- codex가 지적하지 않았지만 확인한 것: `itemsPerPage`가 localStorage에서 비정상 값으로
  들어오면 채움 루프가 커질 수 있다. 다만 이는 **기존에도 있던 성질**이고 select 경로는
  50/100/200/500만 넣는다. 이 티켓에서 다루지 않는다.
