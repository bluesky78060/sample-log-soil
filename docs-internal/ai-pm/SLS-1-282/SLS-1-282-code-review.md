## 판정: **승인**

## 변이 검증이 1년 묵을 뻔한 오판을 잡았다

`max-width: 250px`를 되돌리는 변이를 걸었는데 **시험이 하나도 죽지 않았다.**
보통 이럴 때는 시험이 약한 것인데, 직접 재 보니 그게 아니었다 —
**그 변이가 아무것도 바꾸지 않았다.**

| | 농장주소 폭 | 폭이 바뀐 열 |
| --- | --- | --- |
| `width: 100%` + `max-width: 250px` | **303px** | 1개 |
| `width: 100%` (max-width 없음) | 303px | 1개 |
| `width: 250px` ← **진짜 변이** | 250px | **16개** |

**표 셀의 `max-width`는 열 폭 상한으로 작동하지 않는다.** CSS 2.1은 table-cell의
`min-width`/`max-width` 효과를 아예 정의하지 않고(§10.4), 열 폭은 자동 표 레이아웃이
셀의 `width`를 최소 폭 계산에 넣은 뒤 남는 폭을 분배해 정한다(§17.5.2.2).

### 그래서 SLS-1-279의 판단이 틀렸다

그 티켓에서 퇴비를 범위에서 뺀 근거가 이것이었다.

> `max-width: 250px` 때문에 `width: 100%`를 줘도 **흡수가 아예 일어나지 않는다.**

codex 플랜 리뷰의 지적이었고 **나는 실측 없이 받아들여 문서에까지 옮겼다.**
필요한 변경은 처음부터 `width: 250px` → `width: 100%` 하나뿐이었다.

> 💡 **독립 리뷰의 지적도 실측해야 한다.** 한 줄 실험이면 갈렸을 일이다.
> 변이 검증이 "검출되지 않았다"고 알려 준 덕에 잡혔다 — 시험이 약해서가 아니라
> 변이가 아무 일도 하지 않아서였다. **변이 검증의 음성 결과도 정보다.**

`max-width`는 그래도 지웠다. 아무 일도 하지 않는 선언이 남아 있으면 다음 사람이
"250인데 왜 303이지?" 하고 헤맨다.

## codex MINOR ① — 내 표현이 과했다 · **반영**

"표 셀에서는 `max-width`가 **무시된다**"고 적었는데, 정확히는 **"CSS 2.1이 효과를
정의하지 않고, Chromium의 현재 자동 표 레이아웃에서 열 폭 상한으로 작동하지 않는다"**다.
명세 조항(§10.4·§17.5.2.2)과 함께 주석을 고쳤다.

## codex MINOR ② — `col-address`의 "250px 고정"도 같은 오해 · **반영**

주소 열의 250px는 `max-width`가 **보장하는 상한이 아니다.** 농장주소가 남는 폭을
**먼저 가져가기 때문에** 결과적으로 그 자리에 머무는 것이다. 시험 상수와 주석을
그렇게 고쳐 적었다. 주소 열의 CSS 정리는 이번 범위 밖으로 둔다(codex도 동의).

## codex SUGGESTION — `waitForTimeout` · **반영**

시간이 아니라 **상태**를 기다리도록 바꿨다 — 토글은 `full-view` class가 실제로
뒤집히는 것을, 고정 열 좌표 검사는 rAF 두 프레임을 기다린다.

## 남은 경계조건 (codex 지적, 수용)

남는 폭이 0~수 px인 경계, 빈 농장주소, 매우 긴 단일 토큰 주소, 0건/1건,
전체 보기 상태에서 새로고침, Windows 실제 스크롤바 폭. 1800·2200px 두 점이
임계값 전체를 보장하지는 않는다 — **"넘치면 250px, 남으면 흡수"라는 성질**을 보는
것으로 갈음했다. 경계값 자체는 데이터·글꼴에 따라 흔들려 시험이 깨지기 쉽다.
