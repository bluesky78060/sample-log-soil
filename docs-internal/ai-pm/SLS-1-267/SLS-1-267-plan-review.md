## 자체 검토 — 플랜의 약점 점검

### ✅ 타당하다고 판단한 것

- **(a) config 분기 선택**: `test.skip`은 이 저장소 규약에서 "미구현을 덮는 신호"로
  읽히므로 의도적 조건부 실행에 쓰면 오해를 부른다. config 분기가 맞다.
- **`waitForTimeout(300)` 유지**: `toBeVisible()`은 "DOM에 있고 보인다"까지만 보장한다.
  렌더 애니메이션 중간을 찍을 위험이 있어 캡처에서는 고정 대기가 실제로 유효하다.
- **CI에 캡처를 넣지 않음**: 현재 CI는 Windows 설치본 빌드 전용이고, 캡처를 넣으면
  이미지가 CI에서 갱신되어 커밋 충돌이 난다.

### ⚠️ 스스로 짚은 위험 — 구현에서 반드시 확인할 것

**1. Windows에서 `CAPTURE_MANUAL=1 npx playwright test`가 동작하지 않는다.**
`VAR=1 cmd` 형식은 POSIX 쉘 문법이고 Windows `cmd`에서는 먹지 않는다. 이 저장소는
**Windows 배포가 주 대상**이라 개발자도 Windows일 수 있다. `cross-env` 도입 또는
`--project` 플래그 방식으로 대체할지 구현 중 판단한다.

> 이건 Codex에게 물어보려던 항목(질문 5)인데 답을 못 받았다. **직접 확인한다.**

**2. 분기 실수로 캡처가 영원히 안 돌 수 있다.**
`npm run capture:manual`을 **실제로 실행해** 이미지가 갱신되는지 확인한다.
"설정했으니 되겠지"로 넘어가면 정확히 이 티켓이 막으려던 실패(아무도 안 돌려서 썩는다)를
스스로 만든다.

**3. 기본 E2E 건수 감소를 회귀로 오해할 수 있다.**
감소분이 **정확히 15**인지 확인하고 기록한다. 15가 아니면 의도치 않게 다른 테스트도
제외된 것이다.
