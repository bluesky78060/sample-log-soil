# SLS-1-281 플랜 리뷰

> 정본. 훅 통과용 사본은 `docs/02-review/`.

## 체크리스트

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| 목표 명확성 | ✅ | "시험을 새 계약에 맞춘다" — 무엇이 틀렸는지 특정됨 |
| 범위 적절성 | ✅ | 구현을 건드리지 않는다. 고칠 것은 시험 하나다 |
| 리스크 식별 | ✅ | "상수 확인에 그친다"는 자기 함정을 스스로 짚고 둘째 단정으로 막았다 |
| 산출물 구체성 | ✅ | 줄 단위로 특정 |
| 방향성 일치 | ✅ | Discovery의 "틀린 것은 시험 쪽"과 일치 |
| 기술 검증 | ✅ | stash 대조로 기존 실패임을 확증했다 |
| 테스트 전략 | ✅ | 변이 검증 방향까지 명시 |

## 지적

**1. 시험을 고쳐 초록으로 만드는 것이 은폐가 아닌가** — 아니다. 판별 기준은
"구현과 시험 중 어느 쪽이 옳은가"이고, 여기서는 구현이 옳다는 근거가 분명하다
(SLS-1-280: 모자라면 드러나고 남으면 잘린다). 다만 **그 근거를 시험 주석에 남겨야**
다음 사람이 "왜 정확한 값이 아닌가"를 다시 묻지 않는다. 플랜에 반영할 것.

**2. `>= visible`이 항상 참이라 무력하지 않은가** — 아니다. 구현을 "보이는 열만"으로
되돌리고 전체 보기를 켜면 17 < 19가 되어 깨진다. 그것이 사용자가 신고한 고장이다.

## 판정

**APPROVED (지적 1 반영 조건)** — 시험 주석에 "왜 정확한 값이 아니라 넉넉한 값인가"를
남길 것.
