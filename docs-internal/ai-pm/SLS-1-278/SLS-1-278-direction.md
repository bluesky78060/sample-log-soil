# SLS-1-278 Discovery — 전체 보기에서 보던 열을 잃지 않게

> 정본. `docs/00-discovery/`의 사본은 훅 통과용 일회용이다.

작성: 2026-08-27 · 상태: **방향 확정** (사용자 "진행해줘", SLS-1-276의 후속)

## 목표 (Why)

사용자 요청 "화면 넘김이나 목록 전체보기에서 자연스럽게 넘어가게" 중 남은 축이다.
페이지 넘김은 SLS-1-276에서 끝냈다.

## 범위가 실측으로 절반이 되었다

티켓을 낼 때는 두 축을 담았다. **하나는 실측 결과 문제가 아니었다.**

### ① 화면 전환 — **문제 없음, 이 티켓에서 뺀다**

목업의 진단은 "목록으로 돌아오면 보던 줄이 사라져 맨 위로 간다"였다.
실제 앱에서 재 보니 **스크롤 위치가 이미 보존된다.**

| 시나리오 | 결과 |
| --- | --- |
| 목록에서 400px 내림 → 접수 → 목록 | **400 그대로** ✅ |
| 같은 경로 + `listViewStale=true`(돌아올 때 다시 그림) | **400 그대로** ✅ |

`display:none`이 되어도 브라우저가 스크롤 위치를 잃지 않는다. 고칠 것이 없다.

**겹치기 전환(두 화면을 포개 크로스페이드)도 하지 않는다.** 두 뷰는 `#main-content`의
직계 자식 둘뿐이라 구조상 가능하지만, 겹치면 컨테이너 높이가 **둘 중 큰 쪽으로 고정**된다.
접수 폼이 목록보다 길면 목록 화면 아래에 빈 공간이 생긴다. 0.2초 크로스페이드를 얻자고
레이아웃을 흔들 이유가 없다.

### ② 전체 보기 — **확인된 실제 문제**

가로로 250px 민 상태에서 전체 보기를 켜 봤다 (1280×800, 60건).

| 열 | 이동 |
| --- | --- |
| 체크박스 · 완료 · 접수번호 · 접수일자 · 구분 · 목적 | 0 (왼쪽 고정) |
| **경지구분** | (새로 나타남 — 목적과 성명 **사이**) |
| 성명 | +76 (고정 좌표가 365→435로 바뀜) |
| **우편번호** | (새로 나타남) |
| **주소 · 필지주소 · 기타주소 · 작물명 · 면적 · 전화번호 · 수령방법 · 비고 · 발송일자** | **+150~151 (전부 같다)** |
| 관리 | 0 (오른쪽 고정) |

`scrollLeft`는 250 그대로다. 그래서 **보던 자리가 다른 열을 가리킨다.**

**일반 열이 전부 같은 양만큼 움직인다**는 것이 중요하다. 어느 열을 기준으로 삼든
보정량이 같으므로, `scrollLeft`를 그만큼 밀어 주면 화면이 제자리에 남는다.

보정에 필요한 여유도 있다 — 최대 스크롤이 280 → 431로 늘어난다(250+151=401 ≤ 431).
끄는 방향은 401 → 250이고 최대가 280이므로 역시 가능하다.

## 사용자 (Who)

전국 농업기술센터·분석기관 담당자. 전체 보기는 숨긴 열(우편번호·경지구분 등)을
확인할 때 누른다. 표를 가로로 민 채 누르는 경우가 흔하다.

## 범위 (What)

| # | 대상 | 처방 |
| --- | --- | --- |
| 1 | 신규 공용 모듈 | 열 구성이 바뀌기 전후로 기준 열의 화면 위치를 재고 `scrollLeft`를 보정 (FLIP) |
| 2 | `soil-script.js` `_bindViewToggle` | 그 모듈을 쓴다 |
| 3 | `compost-script.js` `setupColumnToggle` | 같은 구조 — 같이 고친다 |
| 4 | 공용 CSS | 새로 나타난 열에 짧은 페이드 |

## 제약

- **기준 열은 가로로 고정되지 않은 열이어야 한다.** 성명은 `sticky-col`이라
  `left` 좌표가 365→435로 바뀌는데, 그건 스크롤로 되돌릴 수 없다.
  `getComputedStyle(th).left !== 'auto'`인 열은 기준에서 뺀다. 오른쪽 고정(관리)도 뺀다.
- **기준 열은 토글 후에도 남아 있어야 한다.** 전체 보기를 끌 때 첫 일반 열은
  우편번호인데 그건 사라진다. 토글 전에 후보를 여러 개 기억해 두고, 토글 후 **여전히
  보이는 첫 열**을 쓴다.
- 좌표 측정은 `sticky-columns.js`의 재계산과 부딪히면 안 된다. 보정을 끝낸 **뒤에**
  `scheduleStickyColumns`를 부른다 (SLS-1-275의 latch 사고).

## 리스크

| 리스크 | 완화 |
| --- | --- |
| `getBoundingClientRect`가 transform의 영향을 받는다 | 페이지 넘김 애니메이션은 **세로**만 쓴다 — 가로 좌표에 영향 없음 |
| 보정에 필요한 스크롤 여유가 없다 | 켤 때는 표가 넓어져 여유가 늘고, 끌 때는 0 방향이라 항상 가능 |
| 퇴비의 열 구성이 달라 보정량이 열마다 다르다 | 기준 열을 **동적으로** 찾으므로 구성과 무관 |

## 검증

- 유닛: 기준 열 선택 규칙(가로 고정 제외, 사라진 열 제외), 보정량 계산
- E2E: 가로로 민 상태에서 토글 → 기준 열이 화면에서 같은 자리 (토양·퇴비)
- 실기: Electron에서 눈으로
