## ③이 이 티켓에서 가장 큰 발견이다

```css
.data-table { border-collapse: separate; }
.data-table tbody tr { border-bottom: 1px solid #d0d7de; }   /* ← 그려지지 않는다 */
```

**`border-collapse: separate`에서는 행·행그룹·열·열그룹의 border가 명세상 무시된다.**
즉 목록에는 **행 구분선이 처음부터 없었다.** 행마다 들어가는 농가 구분선(초록 줄)
때문에 있는 것처럼 보였을 뿐이고, 같은 성명이 이어지는 구간에는 칸을 나누는 선이
하나도 없었다.

실측(전체 보기, 1900px):

| | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| `tr`의 `border-bottom` | `1px solid #e5e7eb` (**렌더 안 됨**) | 그대로 (여전히 렌더 안 됨) |
| 일반 칸(발송일자)의 `border-bottom` | **`0px`** | `1px solid #d0d7de` |
| 고정 칸(관리)의 `border-bottom` | **`0px`** | `1px solid #d0d7de` |
| 고정 칸(접수번호)의 `border-bottom` | **`0px`** | `1px solid #d0d7de` |

셀에 줘야 하는 이유가 하나 더 있다. **고정 열은 자기 배경(흰색)을 갖고 스크롤되는
내용 위에 떠 있어**, 행에 그린 선이라면 그 배경에 가려 끊긴다. 사용자가 짚은
"발송일자와 관리" 구간이 정확히 그 자리다.

`tr` 쪽 선언은 지우지 않고 남겼다 — 다크 모드의 `border-color`가 그것을 짝으로 삼고
있어서다. **둘 다 아무 일도 하지 않는다는 사실을 주석으로 못 박았다.**

## codex MAJOR — 퇴비 흡수 열은 아예 동작하지 않는다 · **범위에서 뺐다**

플랜 단계에서 잡혔다. 퇴비의 농장주소는 `max-width: 250px`로 못 박힌 **두 줄 표시**
설계라 `width: 100%`가 먹지 않는다. 발현 조건도 2150px 이상으로 훨씬 넓다
(토양은 1700px). 자세한 것은 플랜 리뷰 문서에 있다.

## codex MINOR — 부분적으로 가려진 열이 기준이 될 수 있다 · **수용**

`table-scroll-anchor.js`의 `coveredUntil` 판정은 고정 열에 **일부만** 가린 열도
후보로 남긴다. codex도 "이동량 자체는 동일하므로 현재 UI에서는 영향이 작다"고 달았다.
오른쪽 끝자락이라도 보이면 사용자에게 보이는 것이므로 그대로 두고, 주석에 명시했다.

## E2E가 흡수 열의 부작용을 잡았다

흡수 열을 넣자 **SLS-1-278이 기대던 전제가 깨졌다.** 그때는 "일반 열이 전부 같은
양만큼 움직인다"(실측 +151px)가 성립해 표의 첫 일반 열을 기준으로 삼아도 됐다.
흡수 열은 자기 폭이 변하므로 **그 앞 열과 뒤 열의 이동량이 다르다** — E2E에서
128px 벌어졌다.

기준을 **"지금 화면에 보이는 첫 일반 열"**로 바꿨다. 왼쪽 고정 열이 덮는 구간과
화면 오른쪽 바깥을 빼고 고른다.

### 그리고 재 보니 두 기능은 사실상 겹치지 않았다

codex가 "가로 보정과 흡수 열이 부딪히지 않느냐"고 물어 확인한 결과:

- 흡수 열이 폭을 바꾸려면 표가 화면 안에 들어와야 한다(남는 폭이 있어야 한다)
- 가로 보정이 의미 있으려면 표가 화면보다 훨씬 넓어야 한다

**두 조건이 배타적이다.** 실측(1800px)에서 전체 보기의 가로 여유는 **22px뿐**이었다.
그 사실 자체를 시험으로 남겼다 — 나중에 이 구간이 넓어지면 다시 따져야 한다.

있으면 그것을 열 폭으로 쓰므로, 이미 클래스가 있던 `td`만으로 충분했다.**

기능상 불필요하지만 남겨 뒀다 — 다른 `col-*` 열처럼 머리글과 데이터 칸을 한 이름으로
가리킬 수 있어야 한다. **이 사실을 HTML 주석과 CSS 주석 양쪽에 적었다.**
"통과했으니 지켜진다"고 오해하지 않도록.
