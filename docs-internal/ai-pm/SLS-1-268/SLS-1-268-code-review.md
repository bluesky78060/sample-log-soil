## 지적 및 반영

### MINOR-1 — 케이스 3이 첫 행만 검증한다 (수정 완료)

> 미리보기 렌더링이 **두 행 모두 1번 레코드를 표시하도록 망가져도**, 행 수가 2이고 첫 행
> 값이 맞으면 통과한다.

정확한 지적이다. 이 티켓의 존재 이유가 "통과하지만 아무것도 안 잡는 테스트"를 없애는
것이므로 그대로 두면 자가당착이다.

→ 열 단위 `allTextContents()` 비교로 바꿔 **두 행을 모두** 단언한다. 접수번호·농장명·
대표자·시료종류·축종 5개 열.

### SUGGESTION-1 — 케이스 8이 파일명만 본다 (수정 완료)

> 다운로드된 XLSX가 **비어 있거나 헤더가 틀려도** 파일명만 같으면 통과한다.

수용. 사용자는 이 서식에 맞춰 입력하므로 **헤더가 곧 계약**이다.

→ `download.path()`로 실제 파일을 읽어 `SheetNames`, 헤더 행, 예시 행을 단언한다.

- 테스트 간 상태 누수 없음 (Playwright는 테스트별 context)

### (a)의 결과가 이 티켓의 근거를 그대로 입증한다

배선을 끊은 상태에서:

```
신규 compost-import-flow.spec.js   → 8건 전원 실패  ✅ 잡는다
기존 compost-import-smoke.spec.js  → 1건 통과       ❌ 못 잡는다
```

티켓이 지적한 **"마크업과 전역만 남고 배선이 끊긴 경우에도 통과한다"**가 실측으로 확인됐다.
스모크는 폐기하지 않고 유지한다 — "공용 모듈 생존"이라는 별개 축(SLS-1-224가 soil의 import를
끊을 때 실제로 필요했던 축)을 지킨다.

변이 (b)(c)(d)는 각각 **의도한 케이스만 국소적으로** 죽였다. 단언이 서로 겹쳐 뭉개지지 않았다는
뜻이다. (d)가 케이스 5도 죽인 것은 정상이다 — 케이스 5는 미리보기와 저장의 **일치**를 보므로
미리보기가 망가지면 함께 실패해야 한다.
