# SLS-1-222 플랜 리뷰

## ⚠️ 플랜 리뷰를 수행하지 않았다 (정직한 기록)

`critic` 에이전트 플랜 리뷰를 **실행하지 않았다.** 하지 않은 검증을 했다고 기록하지 않는다.

**사유**: 사용자 지시 — "코드 수정이나 중요가 낮은 작업은 플랜리뷰하지말고 진행해줘".

## 생략을 정당화하는 근거

| 근거 | 내용 |
| --- | --- |
| 결함·원인·수정 지점이 확정됨 | 메인 SAMPL-1-153에서 재현·수정·검증을 마쳤다. 설계 선택지를 탐색하는 단계가 아니다 |
| 이식 대상 코드가 거의 동일 | `soil-result-importer.js`는 메인 수정 전과 1,250줄 중 49줄만 다르고, 그 차이는 CSS·모달 HTML 추출뿐이다. **채번 로직은 바이트 단위로 동일**함을 diff로 확인했다 |
| 함정까지 이미 알고 있다 | 메인에서 회귀 1건(중복 판정을 시퀀스로 나눔)과 MINOR 1건(저장 안 되는 행을 배치 집합에 남김)을 밟았고, 플랜에 둘 다 명시했다 |
| 기존 패턴을 따른다 | `_fns` 노출 + 모듈 레벨 순수 함수는 이 파일이 이미 자동매핑에 쓰는 방식이다 |

## 그래도 남는 리스크와 대응

1. **"같아 보이지만 다른" 부분** — diff가 49줄이라도 `soil-script.js`는 별개다. `addImportedRecord`가 `let receptionNumber`(메인은 `const`)이므로 아래쪽 재대입 코드가 있는지 확인하고 그대로 둔다. `getCurrentLandClass1`·`getStorageKey`·`SampleUtils` 존재도 확인했다.

2. **E2E 인프라 차이** — soil의 `playwright.config` baseURL·webServer와 storage 키를 먼저 읽고 맞춘다. 메인 스펙을 그대로 복사하면 조용히 통과하거나 조용히 실패한다.

3. **메인의 회귀를 그대로 이식하는 것** — 메인은 3커밋에 걸쳐 최종 상태에 도달했다. `979fa90`의 **최종** 코드를 기준으로 이식하고, 중간 커밋(`efa0f0b`)의 시퀀스 분리 중복 판정을 가져오지 않도록 주의한다.

4. **약한 단정** — 이 결함은 형제 프로젝트에서 75건 전부 통과 상태로 새어나갔다. localStorage 기준 + 실제 번호값 정확 일치로 단정한다.

## 코드 리뷰와 적대적 검증은 생략하지 않는다

P1 데이터 무결성이고 운영 코드다. 특히 **메인에서 1차 코드리뷰가 16,000회 차분 퍼징까지 하고 APPROVED를 낸 뒤 적대적 검증이 회귀를 잡았다.** 같은 순서로 진행한다.

생략한 것은 **플랜** 리뷰뿐이다.
