# SLS-1-267 방향 확정 — 설명서 캡처를 기본 E2E에서 분리

**일자**: 2026-08-21
**출처**: SLS-1-223·224 작업 중 반복 관찰 + SLS-1-197 m-2

> 사용자 Q&A 없이 코드 근거로 확정했다. 화면 동작은 바뀌지 않고, 테스트 실행 방식만
> 바뀐다. 되돌리려면 `git revert` 한 번이면 된다.

## 목표 (Why)

두 문제를 함께 잡는다. 같은 파일에 있고, 원인도 "캡처를 매번 무비판적으로 돌린다"로 같다.

### ① 캡처가 매 E2E 실행마다 돈다

`npx playwright test`를 돌릴 때마다 `src/manual/images/*.png` **13개가 수정된다.**
2026-08-20 세션에서만 네 번 되돌렸다.

- `git status`가 무관한 변경으로 채워져 실제 변경을 가린다
- `git add -A`로 **의도치 않게 커밋**될 수 있다 (바이너리라 diff가 크게 잡힌다)
- 되돌리기를 잊으면 설명서 이미지가 조용히 배포된다 — 사용자에게 그대로 보인다

### ② 캡처가 잘못된 화면을 저장해도 통과한다 (SLS-1-197 m-2)

```js
const listBtn = page.locator('#navListBtn, [data-view="list"]').first();
if (await listBtn.count()) await listBtn.click();   // ← 못 찾으면 그냥 넘어간다
await page.waitForTimeout(300);
await page.screenshot({ path: … 'step-15-compost-list.png' });
```

**확인 결과 `#navListBtn`은 compost·soil 어디에도 없다.** 폴백이 아니라 죽은 셀렉터이고,
실질적으로 `[data-view="list"]` 하나에 의존한다. 그것이 깨지면 **테스트는 통과한 채
접수 화면을 "목록" 이미지로 저장해 배포한다.**

이 유형이 특히 나쁘다 — 초록불을 보고 넘어가는데 산출물이 틀렸다.

## 사용자 (Who)

개발자(작업트리 오염 해소)와 최종 사용자(설명서 이미지 정확성).
**앱 동작은 전혀 바뀌지 않는다.**

## 범위 (What)

| 파일 | 변경 |
| --- | --- |
| `playwright.config.js` | `CAPTURE_MANUAL` 환경변수로 project 분기 |
| `tests/e2e/manual-capture.spec.js` | 조건부 클릭 → 단언, 목록 뷰 가시성 확인, 죽은 셀렉터 제거 |
| `package.json` | `capture:manual` 스크립트 추가 |

### 제외

- **`waitForTimeout` 고정 대기 → 조건 대기 교체** (SLS-1-197의 나머지 절반).
  캡처는 애니메이션·폰트 로딩이 끝난 시점을 잡아야 해서 고정 대기가 실제로 필요할 수
  있다. 조건 대기로 바꾸면 "요소는 있지만 아직 그려지는 중"인 순간을 찍을 위험이 있다.
  **별 티켓에서 캡처 품질을 보며 판단한다.**
- 캡처 이미지 자체의 재촬영·품질 개선

## 선택지와 결정

| | (a) config에서 project 분기 | (b) spec에 `test.skip` 게이트 | (c) 출력 경로를 gitignore로 |
| --- | --- | --- | --- |
| 기본 실행에서 제외 | ✅ | ✅ | ❌ (여전히 돈다) |
| 오해 소지 | 낮음 | **`test.skip`은 프로젝트 규약상 blocker 신호** | — |
| 파급 | config 한 곳 | spec 상단 | `copyManualAssets` 구조까지 영향 |

**(a)를 택한다.** (b)의 `test.skip`은 이 저장소 규약에서 "미구현을 덮는 신호"로 읽히므로
의도적 조건부 실행에 쓰면 다음 사람이 오해한다. (c)는 `vite.config.js`의
`copyManualAssets`가 `src/manual/images/`를 빌드 산출물로 복사하는 구조라 위험이 크다.

## 제약 — 캡처 로직이 썩지 않게

🚨 **기본 실행에서 빼면 아무도 안 돌려서 셀렉터가 조용히 썩는다.** 그러면 정작 설명서를
갱신할 때 전부 깨져 있다. ②를 고치는 것이 이 위험의 완화책이다 — 셀렉터가 깨지면
**즉시 실패**하므로, 돌리는 순간 문제가 드러난다.

릴리스 전 `npm run capture:manual`을 돌리는 관례를 CLAUDE.md에 적는다.

## 리스크

| 리스크 | 완화 |
| --- | --- |
| 분기 실수로 캡처가 **영원히** 안 돌게 됨 | `capture:manual`을 실제로 실행해 이미지가 갱신되는지 확인 |
| 단언 추가로 캡처가 실패하기 시작 | 현재 상태에서 먼저 돌려 통과를 확인한 뒤 단언을 넣는다 |
| 기본 E2E 건수 감소를 회귀로 오해 | 감소분이 **정확히 캡처 테스트 수와 일치**함을 확인하고 기록 |

## 검증

- `npx playwright test` → 캡처 테스트가 실행되지 않고, 이후 `git status`가 **깨끗하다**
- `npm run capture:manual` → 캡처만 실행되고 이미지가 갱신된다
- `[data-view="list"]`를 일부러 깨면 캡처 테스트가 **실패한다** (변이 검증)
- 기본 E2E 건수 감소분 = 캡처 테스트 수
