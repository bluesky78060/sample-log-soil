# SLS-1-282 플랜 — 농장주소가 남는 폭을 흡수

> 정본. 훅 통과용 사본은 `docs/01-plan/`.

작성: 2026-08-27 · 근거: `SLS-1-282-direction.md`

## 변경 — `src/compost/compost-style.css`

```css
.compost-navbar ~ .main-content .col-farm-address {
    width: 100%;          /* 250px → 남는 폭을 이 열이 받는다 */
    min-width: 250px;     /* 그대로 — 표가 넘칠 때의 하한 */
    /* max-width: 250px  함께 걷어낸다 (아래 정정 참조) */
}
```

### ⚠️ 정정 — `max-width`가 막고 있던 것이 아니었다

SLS-1-279에서 퇴비를 뺀 근거는 "`max-width: 250px` 때문에 `width: 100%`를 줘도
흡수가 **아예 일어나지 않는다**"였다. codex 플랜 리뷰의 지적을 **실측 없이**
받아들인 것이고, **틀렸다.**

**표 셀에서는 `max-width`가 무시된다.** CSS 2.1이 table-cell에 대한 동작을 정의하지
않고 Chromium은 적용하지 않는다. 변이 검증에서 드러났다 — `max-width: 250px`를
되돌려도 시험이 하나도 죽지 않았고, 직접 재 보니 그 상태로도 농장주소가 **303px**였다.

즉 필요한 변경은 `width: 250px` → `width: 100%` **하나**다.
`max-width`는 그래도 지운다 — 아무 일도 하지 않는 선언이 남아 있으면 다음 사람이
"250인데 왜 303이지?" 하고 헤맨다.

**진짜 변이는 `width`를 되돌리는 것**이고, 그것으로는 시험 2건이 죽는다.

`width: 100%`는 "이 열을 화면 폭만큼"이 아니라 **"남는 폭을 이 열에 몰아라"**다.
다른 열이 내용 폭을 먼저 가져간 뒤 남은 것을 받는다. 표가 이미 넘치면 받을 것이
없어 `min-width`인 250px에 머문다 — **좁은 화면에서는 지금과 완전히 같다.**

`white-space: normal`(두 줄 표시)은 `td` 쪽 규칙이라 건드리지 않는다. 넓어지면
자연히 한 줄에 들어갈 뿐 접힘 자체는 그대로 살아 있다.

## 주소(`col-address`)는 그대로 둔다

같은 250px 고정이지만 **흡수 열은 하나면 된다.** 둘에 걸면 남는 폭을 나눠 가져
"한 열만 변한다"는 목적이 흐려진다. 사용자가 고른 것도 농장주소다.

## 하지 않는 것

| 항목 | 이유 |
| --- | --- |
| 토양처럼 공용 `style.css`에 넣기 | 퇴비 규칙은 `.compost-navbar ~ .main-content` 접두가 붙는다. 그 자리에 두는 것이 기존 구조다 |
| `col-address`도 함께 흡수 | 흡수 열은 하나여야 목적이 선명하다 |
| `white-space` 손대기 | 두 줄 표시는 유지한다 |

## 검증

| 종류 | 내용 |
| --- | --- |
| E2E | 2200px 전체 보기 토글 → **농장주소 외에는 폭이 안 바뀐다** (지금은 16개) |
| E2E | 1800px(표가 넘침)에서는 농장주소가 **250px 그대로** — 설계 의도 회귀 방지 |
| E2E | 데이터 칸의 `white-space`가 여전히 `normal`이다 |
| E2E | 토양은 영향받지 않는다 (선택자에 `.compost-navbar` 접두가 있다) |
| 실기 | Electron에서 눈으로 |

**변이 검증**: `max-width: 250px`를 되돌리면 2200px 시험이 실패해야 한다
(흡수가 막혀 16개가 다시 흔들린다).
