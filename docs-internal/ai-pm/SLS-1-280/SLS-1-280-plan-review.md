# SLS-1-280 플랜 리뷰

> 정본. 훅 통과용 사본은 `docs/02-review/`.

리뷰: 2026-08-27 · 리뷰어: **codex** (독립 레인) + 오케스트레이터 실측

## 판정: **승인 (문구·검증 보완 후)**

CRITICAL 0 · MAJOR 0 · MINOR 2 (반영) · SUGGESTION 3 (반영)

## codex가 확인해 준 것

- **현재 구조에서 충분하다.** 토양 머리글은 22개 고정 셀이고, `gongik-on`과 전체
  보기는 **CSS로 `display`만 바꿀 뿐 셀을 추가하지 않는다.** 따라서
  `head.cells.length`는 어떤 조합에서도 22이고 표시 열 수보다 작아지지 않는다.
- 퇴비 머리글은 25개 고정 셀이고 숨김도 CSS뿐이라 같은 방식이 안전하다.
- 초과 `colSpan`은 브라우저가 실제 열 수로 제한한다.

## MINOR ① — 설명을 정확히 · **반영**

codex: "초과분이 잘린다"보다 **"이 표가 가질 수 있는 전체 열 수를 쓴다"**가 정확한
설명이다. 숨김 열은 그리드에서 빠지므로 결과적으로 초과가 되지만, 의도는 "모자라지
않게 하는 것"이다. 주석을 그렇게 적었다.

## MINOR ② — 앞으로 취약해지는 경로 · **주석에 남김**

`head.cells.length`는 다음에 어긋난다.

- 머리글에 `colspan`이 들어가는 경우 (`cells.length` ≠ 그리드 열 수)
- 머리글 행이 여럿이 되고 첫 행만 보는 경우
- `<th>`를 동적으로 추가하는 경우

현재 두 표 모두 해당 없다. 그때가 오면 그리드 열 수를 세는 방식으로 바꿔야 한다는
것을 주석에 적었다.

## SUGGESTION — 반영

| 제안 | 처리 |
| --- | --- |
| 유닛 기대값을 "머리글 전체"로 고쳐야 한다 | **반영** — 기존 시험이 "보이는 열 수"를 기대하고 있었다 |
| 핵심 E2E는 "기본 보기로 그린 뒤 토글 → **기존** 행의 colSpan 확인" | **반영** |
| `gongik-on` + 전체 보기 조합 | **반영** |
| 시각적 확인만이 아니라 `colSpan === cells.length`도 단언 | **반영** |

## 기각한 대안 — 토글 때 기존 행의 colSpan만 갱신

codex가 "가장 정확한 방식"으로 제시했다. 표시 열 수와 정확히 일치한다는 장점이 있다.

**기각한다.** 채움 행과 구분선을 전부 순회해야 하고(페이지당 최대 100+), 토글마다
그 비용을 치른다. 얻는 것은 "정확한 숫자"뿐인데 화면 결과는 넉넉한 값과 동일하다.
단순한 쪽이 낫다.
