1. 기능 개요

사용자(전국 농업기술센터·분석기관)가 앱에서 문제점·의문사항·건의를 남기고, 관리자(배포자)가 확인·답변하는 게시판입니다.

  • 공지사항 — 관리자가 올린 공지를 모든 사용자가 읽음 (읽기 전용)
  • 1:1 문의함 — 사용자는 본인이 쓴 문의만 보고, 관리자가 답변
  • 익명 인증 — 가입·로그인 없이 앱을 열면 바로 작성 (기기별 익명 UID)
  • 데스크톱(Electron) 전용 — 웹 버전에는 게시판 진입 버튼이 노출되지 않음
키가 없거나 클라우드 미연결 상태에서는 자동으로 로컬 모드(이 PC에만 저장)로 동작하며, 안내 배너가 표시됩니다.

2. 아키텍처 — 게시판은 공유, 시료는 격리

가장 중요한 설계 원칙입니다. 게시판과 시료 데이터의 Firebase 연결을 완전히 분리했습니다.

구분게시판 (문의/공지)시료 데이터 (접수 대장)
공유 범위전국 공유 (개발자가 문의를 한곳에서 수신)센터별 격리 (각 기관 고유)
Firebase 앱named app 'feedbackApp'기본(무명) 앱 firebaseConfig
프로젝트관리자 소유 공유 프로젝트각 센터 자기 프로젝트 또는 로컬
설정 파일feedback-auth.json (Electron 동봉)firebase-auth.json (센터별 입력)
컬렉션feedbackInquiries, feedbackNoticessoilSamples_{년도}
주의: 두 설정 파일이 같은 Firebase 프로젝트를 가리키면 안 됩니다. 시료용(firebase-auth.json)에 게시판 프로젝트 키를 넣으면 시료 데이터가 공유 프로젝트로 섞입니다. 시료는 비워두거나(로컬 유지) 별도 프로젝트를 쓰세요.
격리 보장: 문의는 보안 규칙(ownerUid)으로 사용자 간 분리되어, A센터는 B센터 문의를 볼 수 없습니다. 공지만 공통으로 방송됩니다.

키 비공개 정책 SLS-1-151

Electron은 웹과 동일한 docs/ 빌드를 로드하고 docs/는 GitHub Pages 공개 소스이므로, 키를 렌더러 번들(JS)에 넣으면 무조건 공개됩니다. 그래서:

  • 게시판 키는 렌더러 번들에 절대 포함하지 않음
  • Electron이 런타임에 feedback-auth.json을 IPC로 읽어 설정 주입
  • feedback-auth.json은 .gitignore 처리 → 공개 저장소 미포함, 설치본에만 동봉
  • 커밋되는 것은 feedback-auth.example.json(가짜 값)뿐

3. Firebase 설정 절차

  1. 게시판 전용 Firebase 프로젝트 생성 — console.firebase.google.com (시료/메인과 별개 프로젝트 권장)
  2. Firestore Database 생성 (Production 모드)
  3. 익명 인증 활성화 — Authentication → Sign-in method → 익명(Anonymous) 사용 설정
    이게 꺼져 있으면 게시판 전체가 동작하지 않습니다 (가장 흔한 실수).
  4. 보안 규칙 게시 — Firestore → 규칙 탭에 아래 4장의 firestore.rules 내용을 붙여넣고 게시
  5. 웹 앱 등록 + 설정값 복사 — 프로젝트 설정 → 내 앱 → 웹(</>) 추가 → firebaseConfig 값 복사 (호스팅 체크 안 함)
  6. feedback-auth.json 작성 — 프로젝트 루트의 feedback-auth.example.json을 복사해 feedback-auth.json으로 만들고 실제 값 입력: 
    {
  "apiKey": "AIza...(실제 키)",
  "authDomain": "프로젝트id.firebaseapp.com",
  "projectId": "프로젝트id",
  "storageBucket": "프로젝트id.firebasestorage.app",
  "messagingSenderId": "000000000000",
  "appId": "1:000...:web:..."
}
    measurementId는 불필요(애널리틱스용). feedback-auth.json은 자동으로 git에서 제외됩니다.
  7. (App Check는 설정하지 마세요) — reCAPTCHA App Check는 브라우저+도메인 전용이라 Electron(file://)에서는 동작하지 않고, 강제하면 게시판이 차단됩니다. 키 비공개 + 보안 규칙으로 이미 충분히 보호됩니다.

4. 보안 규칙 (firestore.rules)

게시판 전용(공유) 프로젝트의 규칙입니다. 시료 컬렉션은 두지 않으며(기본 거부), 익명 공개 쓰기 경로를 서버측에서 방어합니다.

rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // 공지: 앱은 읽기만, 작성은 콘솔에서
    match /feedbackNotices/{docId} {
      allow read: if request.auth != null;
      allow write: if false;
    }

    // 문의(1:1): 익명 본인(ownerUid) 글만 생성/조회/삭제
    match /feedbackInquiries/{docId} {
      allow create: if request.auth != null
        && request.resource.data.keys().hasOnly(
             ['ownerUid','org','type','title','body','contact','status','reply','createdAt'])
        && request.resource.data.ownerUid == request.auth.uid
        && request.resource.data.status == '접수'
        && request.resource.data.reply == ''
        && request.resource.data.title is string && request.resource.data.title.size() <= 200
        && request.resource.data.body  is string && request.resource.data.body.size()  <= 2000
        && request.resource.data.org   is string && request.resource.data.org.size()   <= 100
        && request.resource.data.contact is string && request.resource.data.contact.size() <= 100;
      allow read, delete: if request.auth != null
        && resource.data.ownerUid == request.auth.uid;
      allow update: if false;  // 답변/상태는 관리자가 콘솔에서
    }
  }
}
관리자가 콘솔에서 답변/상태를 수정하는 것은 규칙을 우회하므로 allow update: if false와 충돌하지 않습니다.

5. 관리자 운영 — 문의 확인·답변·공지

문의 확인

  • Firebase 콘솔 → Firestore Database → feedbackInquiries 컬렉션
  • 문서 하나 = 문의 하나. 전국 모든 센터 문의가 여기 모입니다.

답변 달기

  1. 해당 문서를 열어 reply 필드에 답변 입력
  2. status를 접수 → 처리중 또는 완료로 변경
  3. 저장하면, 그 문의를 올린 사용자가 앱 게시판을 다시 열 때 "답변" 블록과 갱신된 상태 배지를 봅니다.
실무 팁: 문의에 contact(이메일/전화)가 있으면, 이메일·전화로 직접 회신하는 것이 가장 확실합니다(사용자가 앱을 다시 열지 않아도 전달됨).

공지 올리기

Firestore → feedbackNotices 컬렉션 → 문서 추가:

title:     "시스템 점검 안내"        (문자열)
body:      "6월 20일 14~16시 ..."   (문자열)
createdAt: "2026-06-20"            (문자열)

→ 모든 사용자 앱의 공지 영역에 표시됩니다.

6. 새 문의 알림 받기 (요금제 비교)

콘솔은 자동 알림이 없어 주기적으로 확인해야 합니다. 새 문의가 들어올 때 관리자에게 알림을 보내는 방법:

방법비용알림 채널비고
텔레그램 봇무료폰 즉시 푸시가장 간단·빠름 ⭐
EmailJS무료(월 ~200건)이메일앱이 직접 전송, CSP 도메인 추가
Slack/Discord 웹훅무료메신저웹훅 URL 노출 주의
Firebase Cloud FunctionsBlaze(카드 등록)·저용량 사실상 무료이메일 등Firebase 네이티브
SMS 문자 / 카카오 알림톡유료문자/카톡무료 거의 없음
결론: 요금제가 꼭 필요하진 않습니다. Firebase Cloud Functions만 Blaze가 필요하고, 텔레그램 봇/EmailJS 등으로 무료로 알림받을 수 있습니다. "폰 즉시 알림"이면 텔레그램 봇이 가장 실용적입니다.

구현은 작습니다: addInquiry에서 문서 저장 후 알림 서비스로 전송 + CSP에 도메인 추가 + 봇 토큰/웹훅 URL을 feedback-auth.json(비공개)에 보관. (아직 미구현 — 필요 시 별도 작업)

7. 배포 절차

  1. 로컬 테스트 — feedback-auth.json에 실제 키 입력 후 npm start로 실행, 문의 작성/조회 확인
  2. GitHub Secret 등록 — 저장소 Settings → Secrets → Actions → FEEDBACK_FIREBASE_AUTH_JSON에 feedback-auth.json 전체 JSON 저장
  3. 릴리스 — package.json 버전 올리고 태그 푸시: 
    git tag -a v1.x.y -m "feat: 문의/건의 게시판"
git push origin main
git push origin v1.x.y
    → GitHub Actions가 빌드 시 Secret으로 feedback-auth.json을 생성해 Windows 설치본에 동봉합니다(웹/docs에는 키 미포함).
  4. 첫 공지 등록 — 콘솔에서 feedbackNotices에 환영 공지 추가

8. 트러블슈팅 · FAQ

게시판이 로컬 모드로만 동작해요 (배너가 안 사라짐)

  • 익명 인증이 켜져 있는지 확인 (가장 흔한 원인)
  • feedback-auth.json의 apiKey가 실제 값인지(placeholder 아님)
  • 웹 버전인지 확인 — 게시판은 데스크톱 전용이라 웹에선 로컬 모드
  • 인터넷 연결 / 콘솔(F12)의 [feedback-fb] 로그 확인

문의를 작성했는데 콘솔에 안 보여요

  • 보안 규칙이 게시됐는지 확인 (미게시 시 기본 거부 → 쓰기 실패)
  • 로컬 모드로 저장됐을 가능성 — 위 항목 확인

다른 센터 문의가 서로 보이나요?

아니요. ownerUid 기준으로 본인 문의만 조회됩니다. 단, 익명 UID는 기기/캐시 초기화 시 바뀌어 이전 문의를 못 볼 수 있습니다(설계상 정상).

웹 버전에도 게시판을 넣고 싶어요

그러면 키가 공개 웹에 노출됩니다(현재 (A) 데스크톱 전용 정책). 웹 노출을 감수하려면 별도 작업이 필요합니다.
