# SLS-1-270 Discovery — 혼합 접수번호 채번

작성일: 2026-08-21 · 사용자 승인: "모두 진행해줘" (2026-08-21)

## 1. 목표 (Why)

엑셀 가져오기에서 접수번호가 **일부 행에만** 있으면 나머지 행이 **빈 번호로 저장된다.**
접수번호는 성적서·흙토람 업로드로 나가는 **대외 식별자**라 빈 값은 그 자리에서
접수를 무효로 만든다.

## 2. 사용자 (Who)

퇴·액비 시료를 엑셀로 일괄 접수하는 농업기술센터 담당자.
기존 번호를 유지해야 하는 건과 새로 매겨야 하는 건이 한 파일에 섞이는 것은 자연스럽다.

## 3. 범위 (What)

### 포함
- `src/shared/excel-import-manager.js`의 `_autoAssignReceptionNumbers` 수정
- `tests/e2e/compost-import-flow.spec.js` 케이스 7을 새 동작으로 갱신

### 제외 — 정렬 역전은 건드리지 않는다
`compost-script.js:2397`의 `parseInt('') || 0` 정렬이 빈 번호를 목록 맨 앞에 놓는다.
**이번 수정으로 가져오기가 빈 번호를 더는 만들지 않으므로 발생원이 사라진다.**
남는 것은 과거에 저장된 레코드뿐이고, 그것들이 맨 위에 보이는 편이 오히려 눈에 띈다.
정렬을 바꾸면 **모든 사용자의 목록 순서가 바뀌므로** 이번 변경에 끼워 넣지 않는다.

## 4. 제약

- 이 모듈은 **공용**이다. 현재 소비자는 compost뿐이지만(soil은 SLS-1-224에서 분리)
  다른 시료 종이 붙으면 함께 딸려간다 → 특정 종에 맞춘 가정을 넣지 않는다
- `autoNumberExtract` / `autoNumberFilter` 설정 훅을 계속 지원해야 한다
- 기존 동작 두 가지는 **바뀌면 안 된다**
  - 전 행에 번호 있음 → 전부 보존 (자동 채번 없음)
  - 전 행에 번호 없음 → 기존 최대값 + 1부터 연번

## 5. 우선순위

P3. 남은 티켓 중 **유일하게 사용자 데이터에 영향**이 간다.
SLS-1-268이 현재 동작을 케이스 7로 고정해 두어 지금이 고치기 가장 좋은 시점이다.

## 6. 리스크

| 리스크 | 대응 |
| --- | --- |
| 자동 채번이 배치 안의 명시 번호와 충돌 | **전체 최대값 위에서 시작**해 구조적으로 불가능하게 한다 |
| 기존 두 경로가 회귀 | 케이스 5·6이 이미 그것을 지킨다. 변이 검증으로 실제로 죽는지 확인 |
| 공백 문자열(`'   '`)이 번호로 취급됨 | `trim()` 후 판정 |
| 400자리 번호가 `parseInt` → `Infinity` | `Number.isSafeInteger`로 거른다 (soil의 SLS-1-223과 같은 방식으로 통일) |

## 7. 검증

- 케이스 7을 새 동작으로 바꾸고 **변이 검증**으로 실제로 죽는지 확인
- 케이스 5·6 회귀 없음
- 전체 E2E·단위·린트 통과
