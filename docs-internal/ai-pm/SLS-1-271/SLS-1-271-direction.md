# SLS-1-271 Discovery — 퇴비 가져오기 경계조건 E2E

작성일: 2026-08-21 · 사용자 승인: "모두 진행해줘"

## 1. 목표 (Why)

SLS-1-268이 정상 경로를, SLS-1-270이 채번을 덮었다. **남은 것은 실패 경로다.**
가져오기가 거절해야 할 입력을 조용히 통과시키면 쓰레기 레코드가 대장에 남는다.

## 2. 사용자 (Who)

엑셀을 손으로 만들어 올리는 담당자. 헤더만 있는 파일, 빈 행이 섞인 파일,
서식과 다른 파일은 **실수로 자주 생긴다.**

## 3. 범위 (What)

`tests/e2e/compost-import-boundary.spec.js` 신설. 5개 분기:

| # | 분기 | 코드 |
| --- | --- | --- |
| 1 | 헤더만 있는 파일 | `jsonData.length < 2` |
| 2 | 빈 데이터 행만 | `_excelData.length === 0` |
| 3 | 매핑 0개 | step2 진행 차단 |
| 4 | `skipRowCheck` 전건 탈락 | 미리보기 0건 → 가져오기 차단 |
| 5 | 5000행 초과 | `MAX_IMPORT_ROWS` 절단 |

### 제외
- `src/` 변경 없음. 결함을 발견하면 **별도 티켓**으로 올리고 테스트는 현재 동작을 고정한다

## 4. 제약

- `MAX_IMPORT_ROWS`는 `_handleFileSelect` 안의 지역 상수라 **주입할 수 없다.**
  5001행 픽스처를 실제로 만들어야 한다 → 생성·파싱 시간을 먼저 재고, 감당 못 하면
  그 항목만 빼되 **뺐다는 사실을 명시한다** (조용한 축소 금지)
- 1·2번은 모달이 아예 열리지 않는다 → "모달이 안 보인다"로 단언한다.
  toast 문구는 보조로만 쓴다 (문구는 쉽게 바뀐다)

## 5. 우선순위

P4. 사용자 데이터를 지금 망가뜨리고 있지는 않다.

## 6. 리스크

| 리스크 | 대응 |
| --- | --- |
| toast 문구에 의존해 취약해짐 | **상태**(모달 가시성·단계·미리보기 행 수·저장 건수)로 단언 |
| 5000행 테스트가 느려 전체 실행을 늘림 | 시간을 재고 판단. 오래 걸리면 행 수를 줄일 방법을 찾거나 제외 |
| 4번이 죽은 분기일 가능성 | compost의 `buildRecord`가 `sampleType`에 기본값을 넣는다 — **확인 필요** |

## 7. 검증

- 5개 분기 각각 **변이 검증** — 해당 가드를 없애면 테스트가 실제로 죽는가
- 전체 E2E 회귀 없음
